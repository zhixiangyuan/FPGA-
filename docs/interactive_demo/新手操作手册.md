# AFDX 新手操作手册

现在按三个视频准备演示。打开 `D:\FPGA\功能演示`，主目录中使用下面三个启动文件。原来的 01～09 单项入口保留在「单项测试入口」子文件夹中，正常录制不需要逐个打开。

| 视频 | 启动文件 | 要展示的内容 |
|---|---|---|
| 视频一：系统基础功能 | `视频1_系统基础功能演示.cmd` | 原 1～6，整合在一个控制窗口中，最后展示六项结果汇总 |
| 视频二：系统性能 | `视频2_系统性能展示.cmd` | 原 7，展示吞吐、时延、极差和同 VL 发送间隔的实际测量值 |
| 视频三：调度优化对照 | `视频3_调度优化对照演示.cmd` | 原 8，相同输入下比较优化前后两套新仿真 |

单帧消息、错误注入文本和 SNMP SET 值默认都是 `I LOVE FPGA`，包含两个空格，共 11 个 ASCII 字节。可以直接使用，也可以修改。VLID、帧数、字节数、间隔、SN 和时间偏移必须是有效数字，不填这段文字；批量数据由测试环境按公开公式生成。

## 一、整合后怎样使用

### 一个窗口，六个功能页和一个结果汇总页

视频一的窗口上方有 01～06 六个功能页，以及「结果汇总」。从左到右演示；每次运行都由你点击按钮启动。切换功能页时，程序自动保存结果并结束上一项的 ModelSim，再为尚未运行的下一项加载独立仿真，不需要你手动关闭和打开六个程序。

各项独立初始化：双网故障不会带到错误校验或管理测试；序号不会跨功能页串用；SNMP 保留的是本项内实际写入的值；RTC 功能页会加载自己的新请求。自动初始化不会替你发送业务消息、注入错误报文或执行 GET/SET。

已经运行过的功能页保留最后结果，可以切回查看。若在已结束仿真的页面再次点击测试按钮，会开启该项的新实验并清空该项汇总进度，其他功能页的已完成结果保留。链路页重新初始化时恢复「双网正常」。RTC 已同步后再次点击响应，会自动为新参数加载一套独立校时仿真。

### 每次操作按四步进行

1. 等上方显示「等待本人操作：仿真已加载并停在 100 μs」。100 μs 是初始暂停位置，不是报错。
2. 核对或修改输入，再点击本手册指定的按钮。
3. 运行期间等待结果，不重复点击，也不切换功能页；程序会阻止运行中的页面切换。
4. 完成后看「本次操作」「功能核对」以及本次实际结果，再看适用指标。结果较多时向下滚动。

修改文本的方法：用鼠标点输入框 → 同时按 Ctrl+A 选中原文字 → 输入新内容。改文字不会启动测试。修改链路下拉框后，必须先点「应用所选故障／恢复」，等完成，再点发送。

运行时旧结果会替换为「仿真运行中，结果待生成」，完成后才显示新结果。输入相同的 `I LOVE FPGA` 时，文字本身可以不变；请看本次计数变化和帧序号，确认这是新一次操作。

### 怎样读结果

| 结果 | 含义 |
|---|---|
| 功能核对：通过 | 实际字节、格式、校验、序号或管理响应与独立参考一致 |
| 发送 +1；交付 +1 | 本次发送一帧，应用新收到一帧 |
| 发送 +1；交付 +0；无新数据 | 本次发送了，但没有新应用交付；看所选故障或序号异常判断原因 |
| 消重 +1 | A/B 两个合法副本只向应用交付一次 |
| 本次 MAC 丢弃／业务解析器拒绝／序号异常 | 本次点击新增的计数，不是旧会话的累计值 |
| 实测值后有达标或未达标 | 有充分依据时给出对应状态，只限本次样本或负载 |
| 只有实测值或样本不足 | 没有明确数值判据、不是性能负载或没有足够样本；不附达标结论 |
| 本会话累计 | 当前功能页这一套仿真的总数，不是六个功能页合计 |

功能核对通过与性能达标分开。错误报文被正确拒收、双网断开时没有新交付，都可以是功能核对通过。结果只显示实际值和有依据的达标状态，不列比赛要求数值。极差缺少明确数值门槛，因此只显示测量值；模拟校时不证明绝对 UTC 精度。

## 二、视频一：系统基础功能

双击 `视频1_系统基础功能演示.cmd`。窗口会先加载 01，其他功能页在首次切换时加载。首次编译可能需要几十秒；录屏成片可以裁掉编译等待，但必须保留你实际选择参数、点击按钮以及真实结果。

### 第 1 项：业务收发与帧格式

**测什么：** 本人填写的数据经过封装、双网发送、接收校验和消重后能否原样交付。

默认 VLID=`1234`，单帧数据=`I LOVE FPGA`。

1. 等待 01 加载完成。
2. 点击「发送本人输入的数据」。
3. 看结果：发送 +1 帧、交付 +1 帧、消重 +1 次，实际接收内容为 `I LOVE FPGA`，载荷 11 字节，VLID 为 `0x1234`。
4. 想展示修改后的效果，把数据改为 `I LOVE FPGA 2026`，再点发送。实际内容应改变，载荷从 11 变为 16 字节，SN 增加，HEX 和 FCS 也随报文字节变化。没有新输入就不会自动发送。
5. 本项汇总应显示「完成」。点击 02 功能页继续。

**看波形：** `tx_data/tx_valid` 是应用输入，`rx_data/rv` 是应用输出；`rv` 高时 `rx_data` 才有效，`rs/re` 标记首尾。数据变长时有效数据持续时间变长。程序会自动缩放最近接收附近，两张图比例尺可能不同，比较宽度时先保持相同时间刻度。

**可以这样讲：**「我输入 I LOVE FPGA，接收端读回相同的十一字节数据。修改内容后，接收内容、长度和报文字节也相应改变。」

### 第 2 项：多 VL 与 BAG 调度

**测什么：** 四个通道是否分别完整交付，同一通道的实际发送间隔是否符合当前 BAG 配置。

| 输入框 | 默认值 |
|---|---:|
| VLID | `1234` |
| 单帧文本 | `I LOVE FPGA`，本次批量不使用这个框 |
| 批量帧数 | `32` |
| 批量 VL 数 | `4` |
| 每帧有效载荷字节数 | `64` |
| 应用输入间隔 | `33000` |

1. 点击 02 功能页，等待加载完成。
2. 保留默认参数，点击「确认参数并生成批量负载」。不要点上面的单帧发送按钮。
3. 弹窗核对 32 帧、4 VL、64 字节、33000 周期，点击「是」。
4. 看本次发送 +32、交付 +32。各 VL 应为 `1234=8 帧；1235=8 帧；1236=8 帧；1237=8 帧`。
5. 看「本次同 VL 最小发送间隔」的实际值和达标状态。本项的小包吞吐只显示实际值，不作为持续性能负载判定。
6. 本项汇总应显示「完成」。点击 03 继续。

要另外练习参数变化，可以把 VL 数改为 2 再运行，本次各通道应各交付 16 帧。输入按通道轮转提交，最终线上顺序由调度器决定，不要求始终严格按通道编号排列。

批量载荷不是文本框里的 I LOVE FPGA，而是公开字节模式：`(53 + 帧号×13 + 字节位置×37 + (字节位置>>2)) mod 256`。结果出现二进制载荷和 HEX 是正常的。各通道至少交付两帧后，才有同 VL 间隔样本；只发一条短消息不能完成这项调度验证。

**看波形：** `a/b` 是双网发送字节，`ae/be` 高表示发送有效；`dut/app_sent` 与 `dut/rx_delivered` 增加。自动定位只展示最后接收附近；要看整批，在 ModelSim 点 Zoom Full 后放大本次发送区间。

**可以这样讲：**「这次三十二帧分配到四个通道，每个通道交付八帧，同时核对同一通道的实际发送间隔。」

### 第 3 项：双网故障、恢复与消重

**测什么：** 双网正常只交付一次；单网能继续交付；A 接收错误时 B 有效；双网断开不交付；恢复后能重新交付。

1. 点击 03，等待独立仿真加载。VLID 保持 `1234`，文本保持 `I LOVE FPGA`。
2. 第一行默认双网已经生效，直接发送。
3. 后续每一行都按「选择链路 → 点应用 → 等完成 → 点发送 → 等完成」操作。文本不需要反复修改。

| 顺序 | 链路选择 | 发送后看什么 |
|---|---|---|
| 1 | 双网正常 | 发送 +1、交付 +1、消重 +1；收到 I LOVE FPGA |
| 2 | 断开 B，仅 A | 已生效链路为仅 A；交付 +1 |
| 3 | 断开 A，仅 B | 已生效链路为仅 B；交付 +1 |
| 4 | A 接收错误，B 正常 | A MAC 丢弃 +1，B 丢弃 +0，仍交付 +1 |
| 5 | 双网断开 | 发送 +1、交付 +0，明确显示「本次实际接收：无新数据」 |
| 6 | 双网正常 | 再次发送后交付 +1，实际收到 I LOVE FPGA；恢复时的序号异常、消重按实际状态显示 |

完成六种情况后，本项汇总才显示「完成」。仅在双网正常下发一次，汇总保持「进行中」。所有消息一样也能分辨：每次看「本次」增量和最近发送帧 SN，不能只比较文本。

恢复前同一网络可能连续错过多帧，第一帧可能触发跳号拒收；这是当前序号检查策略。界面会显示本次序号异常，不能把旧数据当新数据。本表顺序已经包含可交付的恢复案例；不要随意连续断网发送几十次后再套用表中的结果。想重做独立实验，切到别页再回本页，点击测试会为本项重新初始化，或使用本项尚未用过的 VL。

**为什么还有波形：** 断开的是测试链路返回方向，时钟和发送端仍然工作。看 `rv` 与交付计数，不是看有没有波形。`mask` 的 3/1/2/0 分别表示双网/仅 A/仅 B/双断；`error_a` 表示 A 错误注入。`net_valid` 是测试环境内部流，不代表断网后 DUT 一定收到。

**可以这样讲：**「我依次断开 A、B，另一条链路仍能交付；两条都断开后，没有新数据交付；恢复双网后又能收到。」

### 第 4 项：错误校验与异常序号

**测什么：** 错误报文和异常序号不能直接进入应用；错误帧不污染正常接收。

点击 04 并等待加载。默认 VLID=`12A0`、数据=`I LOVE FPGA`、SN=`1`、类型=正常报文。文本整项不变。按下面每一行改类型和 SN，再点「注入本人选择的对端报文」。

| 顺序 | 报文类型 | SN | 本次应看到的结果 |
|---|---|---:|---|
| 1 | 正常报文 | 1 | 交付 +1，实际收到 I LOVE FPGA |
| 2 | FCS错误 | 2 | 无新数据；MAC 丢弃 A/B 各 +1 |
| 3 | IP校验错误 | 2 | 无新数据；业务解析器拒绝 A/B 各 +1 |
| 4 | UDP长度错误 | 2 | 无新数据；业务解析器拒绝 A/B 各 +1 |
| 5 | 正常报文 | 2 | 交付 +1，说明前面的错误帧未污染正常序号 |
| 6 | 正常报文 | 9 | 无新数据；序号异常增加，两网各检查一次 |

不要在第二、三、四行反复增加 SN：这三行都填 2，第五行仍填 2。第六行改为 9。完成后本项汇总显示「完成」。想继续验证异常后接收，可把正常报文的 SN 改为 10 再注入，应该重新交付。

本项从对端 GMII 注入，不经过应用发送口，因此应用发送 +0 正常。错误帧本身仍有输入波形；看 `rv` 是否产生对应有效消息，以及 `dut/mac_a_dropped`、`dut/parser_a_rejected`、`dut/rx_integrity_errors` 的变化。IP/UDP 错误帧仍带正确 Ethernet FCS，才能分别验证上层检查。

**可以这样讲：**「我保持载荷不变，分别修改校验和序号。错误在对应处理层被拒收，正常报文才交付给应用。」

### 第 5 项：SNMP GET、SET、再 GET

**测什么：** 从真实报文读取设备信息，通过网络写入新值，再重新读回已保存的值。

点击 05，等待加载。默认对象=`4 · sysContact`，SET 值=`I LOVE FPGA`。

1. 点「GET：从真实响应读取」。实际响应值应为初始值 `afdx-es-team3`。汇总仍为进行中。
2. 保留默认 SET 值，点「SET：写入本人填写的值」。实际响应值应变成 `I LOVE FPGA`。汇总仍为进行中，因为还没有重新读回。
3. 再点 GET。实际响应值仍为 `I LOVE FPGA`。至此汇总显示完成。
4. 可以改填 `I LOVE FPGA 2026`，再点 SET、GET，观察新值保存。只改输入框不等于写入。

SET 只支持 1～32 个 ASCII 字节。英文、数字、空格、英文标点都可以，中文会在执行前被拒绝，不会写入 DUT。切到其他功能页后再回来，最后结果仍可查看；再次执行测试会为本项开新仿真，设备信息恢复初始值，本项汇总重新累计。

应用发送/交付为 0 正常；SNMP 走管理路径。业务解析器拒绝 A/B 可能增加，因为管理报文不属于普通业务配置；这不代表 SNMP 失败。看实际响应值、错误状态 0、本次请求/响应 +1/+1。请求首字节至响应末字节的耗时只显示实测值。

**看波形：** `dut/snmp_requests`、`dut/snmp_responses` 每次增加。`rx_data/rv` 是业务输出，不用于直接显示管理字符串；优先展示中文结果中的实际响应值。

**可以这样讲：**「先读初始联系人，再写入 I LOVE FPGA，最后重新读取。这里的值来自真实响应报文，不是输入框的预期内容。」

### 第 6 项：RTC／SNTP 校时

**测什么：** 设备能否处理模拟时间服务器的应答，按四个时间戳计算并更新 RTC。

1. 点击 06，等待独立仿真加载。新的时间请求由设计自己发出，不会沿用前几项的请求。
2. 默认偏移保留 `250` 微秒，点击「发送本人确认的时间响应」。
3. 看 RTC 同步状态 `0 → 1`、四时间戳计算核对通过，以及实际 offset、delay。汇总显示完成。
4. 想比较参数变化，可以改填 `500` 再点响应。整合入口会自动新开本项独立仿真，再发送你确认的响应；不必手动关闭整个基础功能窗口。

输入的 250 是服务器时间戳参数，不要求最终 offset 等于 250。offset 按 `(t2−t1+t3−t4)/2`、delay 按 `(t4−t1)−(t3−t2)` 计算。服务器由测试环境模拟，绝对 UTC 精度仍是未测量；不宣称连接了真实互联网服务器。

**看波形：** `ts` 由 0 变 1；查看 RTC UTC 与 `sntp_t1`～`sntp_t4`。时间戳是 NTP Q32.32 格式，不是直接显示微秒的普通整数。

**可以这样讲：**「设备发出时间请求后，我提供模拟服务器响应。同步标志由零变一，实际 offset 和 delay 通过独立计算核对。」

### 最后：展示六项汇总

1. 等第六项运行完成，点击「结果汇总」。
2. 顶部应显示「基础功能完成：6 / 6 项」。六行分别显示完成和实际已覆盖的子测试。
3. 如果少于 6，查看下方「尚未完成」列表。不要把没测过的项目解释成已通过；按对应功能页完整顺序重做该项。
4. 汇总页可以保留为视频一结尾。切回旧功能页只查看不重测，不会改变汇总；再次运行会开启新实验并重置该项进度。

汇总保存到 `build\interactive_suite\本次时间\summary.json`，关联各功能页独立原始运行目录。它证明当前记录的子测试，不代表完整正式验收或全部协议认证。

## 三、视频二：系统性能展示

关闭基础功能窗口，再双击 `视频2_系统性能展示.cmd`。默认 VLID=1234、64 帧、16 VL、每帧 1471 字节、输入间隔 8100 周期。单帧文本已填 I LOVE FPGA，但本次批量不使用它。

1. 等待加载。
2. 点「确认参数并生成批量负载」，核对弹窗后点「是」。
3. 看发送 +64、交付 +64、未交付 0；各通道交付 4 帧。
4. 展示本次有效载荷吞吐、应用首字节至末字节最大观测时延，以及对应达标状态。
5. 展示同 VL 同长度时延极差的实测值、同 VL 最小发送间隔及对应状态。极差没有明确数值判据，不附达标标签。

要比较输入速度变化，重启视频二，其他参数保持不变，仅把间隔改为 33000 再测试，实际吞吐会降低；显示未达标只针对这次较慢输入负载。不要把不同输入条件当成优化前后收益。

吞吐只计一次有效载荷，不重复计算 A/B，也不把 VLID 或协议头算进去。时间窗口包含本次第一帧应用输入首字节至最后一帧输出末字节。时延包含排队、调度、测试链路与接收；最大观测值不是任意负载的全局最坏时延。极差按同 VL、同长度分组统计，每组至少两帧；样本不足不显示为零抖动。

**可以这样讲：**「这次使用固定正常批量负载，先确认全部交付，再按实际输入输出时刻计算吞吐和时延。」

## 四、视频三：调度优化对照

双击 `视频3_调度优化对照演示.cmd`。固定负载为 24 帧、16 VL、1471 字节、8100 周期，并包含两个管理请求突发，不需要填写文本或参数。

1. 等待优化前、优化后两套 ModelSim 都加载并停下。
2. 点「确认条件并开始两套新仿真」，核对后点「是」。
3. 等「本次对照 PASS」，展示两侧实际吞吐、最大观测时延、极差以及变化百分比。
4. 展示实际输入一致性核对结论。任何一侧失败或实际输入不一致，都不能算有效优化对照。

这是管理积压压力下的调度优化演示，使用已验证配套历史生产 RTL 快照，两侧仅仲裁器不同；不是当前所有 RTL 的优化收益，也不是正常对端 BAG 负载。01～07 使用当前活动 RTL。实际收益以这次新仿真为准，不承诺固定百分比。

**可以这样讲：**「两套设计的输入字节和时刻完全相同，只改变发送仲裁器，比较本次管理积压压力下的实际性能。」

## 五、录制与常见问题

三个视频分别录制，标题写明 RTL 仿真。视频一可以裁掉各页加载等待，但保留本人点击、修改和真实结果。视频二、三的结果必须带上实际负载条件，不能把历史数字贴成新实测值。详细剪辑分配见同目录《三分钟讲解与录屏步骤》。

| 现象 | 处理方法 |
|---|---|
| 切换功能页后等待几十秒 | 下一项正在编译独立仿真，等状态显示等待本人操作 |
| 运行时不能切页 | 等当前操作完成，防止中途终止并产生不完整结果 |
| 同样的文字看起来没变 | 看本次交付增量、SN、类型和链路，消息内容本来就一样 |
| 改链路后结果不符 | 先点应用，核对已生效链路，再发送 |
| 只点一次，汇总仍是进行中 | 有些项目包含多种子测试，查看汇总的尚未完成列表 |
| 双断仍有发送波形 | 时钟与发送仍工作；看本次交付为 0 和无新数据 |
| 恢复后第一条没收到 | 看本次序号异常；不要连续乱点，换未用 VL 或为该项开启独立新实验 |
| 业务解析器拒绝增加，SNMP 却通过 | 两条处理路径不同；看实际管理响应和请求/响应计数 |
| 修改数据却没执行 | 输入框修改不会运行，必须点击对应按钮 |
| 功能通过但性能未达标 | 功能和性能是不同结论，核对是否使用视频二默认负载 |
| 功能失败或超时 | 停止该项并保留日志；不能把失败片段作为通过证据 |
| 窗口还是旧版 | 关闭旧窗口及对应 ModelSim，重新启动新的视频入口 |

原 09 是工程与综合报告证据，不是动态功能测试。在「单项测试入口」中打开即可，不必单独拍视频。报告与当前交互源码是否一致，以源码指纹为准。不要执行 Implementation、Bitstream 或硬件下载。
