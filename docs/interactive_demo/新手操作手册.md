# AFDX 中文交互演示操作手册

交付入口在 `D:\FPGA\功能演示`。先双击 `01_业务收发与帧格式演示.cmd`。等待中文窗口显示「等待本人操作」，再输入数据并发送。ModelSim 会自动检查许可、编译正式源码、加载设计和添加波形；不会替使用者发送业务数据。

## 开始前

- 保留工程 `D:\FPGA\captain_integration`。交付目录是启动工具，不是另一套工程。
- 本机 Python：`E:\ICAN\PYthon-3.10\python.exe`；ModelSim：`D:\FPGA\Modlesim20.4\ModelSim20.4\win64\vsim.exe`。路径变动时修改 `launch.ps1`；ModelSim 也可通过 `MODELSIM_BIN` 环境变量指定其 win64 目录。
- 首次编译可能需要几十秒。出现许可错误时，先检查 `MGLS_LICENSE_FILE`；未设置时使用 ModelSim 安装目录的 `LICENSE.TXT`。本工具不修改系统许可设置。
- 每次只录一个入口。录完关闭中文控制窗口和对应 ModelSim；关闭控制窗口会保留 ModelSim 波形，便于检查。
- 首次加载后仿真停在约 100 μs。此时只有设计自身的 SNTP 请求，没有自动发送业务数据。等待时不推进仿真时间。

## 窗口中的三个状态

| 状态 | 含义与下一步 |
|---|---|
| 等待本人操作 | 可填参数、点击按钮 |
| 真实仿真运行中 | 不重复点击，等待结果 |
| 本次独立核对通过 | 本次累计输入对应的真实双网输出、应用输出和适用的协议结果与独立参考一致；可以继续操作 |
| 本次核对失败／超时 | 保留日志，重新启动入口。不要将该段录成成功证据 |

这里的 PASS 是新交互场景 RTL 核对结果，不是完整正式验收、网表验证、上板结果或全协议合规结论。

## 01 业务收发与帧格式

1. 双击入口，等待加载。
2. 将 VLID 填为 `1234` 或 `1235`，均按十六进制解释。
3. 在数据框输入自己的内容，例如 `评委现场输入1029`。数据按 UTF-8 转为字节，长度须为 1～1471 字节。
4. 点击「发送本人输入的数据」。
5. 看中文结果中的实际应用输出、HEX、真实 GMII 的 VLID、UDP 载荷长度、SN 和 FCS。
6. 切到 ModelSim，查看 `tx_data/tx_valid/tx_ready`、`a/b`、`ae/be` 和 `rx_data/rv/rs/re`。波形会定位最近一次实际接收附近。

VLID 范围为 `1234`～`12B3`，对应正式顶层配置的 128 个业务 TX VL。应用接口每帧先输入两个 VLID 字节，再输入载荷；低 `tx_valid` 周期结束一帧。工具等待 `tx_ready` 后驱动顶层端口。

真实路径：应用输入 → 正式发送队列、BAG 调度、协议封装及双 MAC → 测试链路 → 正式 MAC 校验、协议解析、序号检查、消重 → 应用输出。测试链路是串行帧队列，B 比 A 延迟 64 个 125 MHz 周期。它不是外部设备互操作证明。

## 02 多 VL 与 BAG 调度

1. 先分别输入 VLID `1234`、`1235`，各发送一条自己输入的短消息。
2. 需要展示调度时，填写批量参数。可用：帧数 `32`、VL 数 `4`、长度 `64`、输入间隔 `33000` 周期。
3. 点击「确认参数并生成批量负载」，核对弹窗中的实际参数后确认。
4. 看最小同 VL 发送间隔与各 VL 的实际交付。固定 BAG 为 125000 周期，即 1 ms，不会为了录制而缩短。

批量数据由测试环境生成，公式为 `(53 + 帧号×13 + 字节位置×37 + (字节位置>>2)) mod 256`。帧数超过 1 时使用该公开模式，不能称为本人逐字输入。VL 按基值开始轮转。单帧入口始终发送本人填写的数据。

## 03 双网故障、恢复与消重

1. 保持「双网正常」，输入 VLID `1234` 和消息 `双网正常`，点击发送。正常情况下，应用交付一帧，消重计数增加一次。
2. 选择「断开 B，仅 A」，点击「应用所选故障／恢复」。
3. 修改消息为 `仅A传输`，本人再次点击发送。应用仍应收到新消息。
4. 选择「断开 A，仅 B」，应用选择后，再发送另一条新消息。
5. 选择「A 接收错误，B 正常」，应用选择后，发送新消息。观察 A MAC 丢弃和 B 的有效交付。
6. 选择「双网正常」，应用恢复后再发送新消息。观察交付和消重。

「双网断开」也是有效负例：随后发送的帧仍会从真实双 MAC 发出，但链路不返回数据，应用不会收到。核对通过表示观测与所选故障一致，不表示双网同时断开还能交付。

同一网络连续缺失多帧后，恢复时可能触发正式序号检查。不要把该结果隐藏为工具错误；日志会记录序号异常。简短录屏按上述每阶段一帧操作，或换一个新 VL 开始独立实验。恢复不清空 DUT 的序号状态。

## 04 错误校验与异常序号

该入口模拟对端，从 GMII 注入完整以太网字节，经过真实 MAC、解析器及接收状态机。发送应用与输入对端报文是两个不同方向。

1. 保持对端 VLID `12A0`，填入自己的数据，SN 填 `1`。
2. 选择「FCS错误」，点击注入。应用不得出现该数据，MAC 丢弃增加。
3. 保持 SN 为 `1`，选择「IP校验错误」，再次注入。该报文重新计算 Ethernet FCS，测试真实 IP 校验；应用不得交付。
4. 保持 SN 为 `1`，选择「UDP长度错误」，再次注入。该报文也有正确 Ethernet FCS，测试真实 UDP 长度检查。
5. 选择「正常报文」，SN `1`，点击注入。应首次正常交付，证明错误帧没有污染正常 SN 状态。
6. 将 SN 改为 `9`，正常注入。相对于当前状态属于异常跳号，应观察完整性错误和未交付。

可进一步测试 `255→1` 环回、允许的 +2 跳号、重复 SN、SN0 控制记录。建议重新启动入口后使用独立 VL。SN0 是控制记录，不应作为业务载荷交付；相同 SN 再从同一网到达可能计入序号错误，A/B 同一合法序号的第二份报文才用于展示冗余消重。独立参考会按正式策略核对，而不会把所有重复统称为同一种原因。

## 05 SNMP GET／SET／再 GET

1. 选择 `4 · sysContact`。
2. 点击「GET：从真实响应读取」。查看实际响应字符串。
3. 在 SET 框填写自己的 ASCII 值，例如 `team1029`。不得留空，最长 32 字节。
4. 点击「SET：写入本人填写的值」。
5. 再次点击 GET，查看实际响应中保存的值。

也可选择 `sysName`、`sysLocation`。GET 使用 public，SET 使用 private；采用工程已验证的 SNMP v1 BER 参考。请求、响应都经过真实 GMII 与管理链路。窗口里的「期望值（待核对）」不是 DUT 结果；只有实际响应全字节匹配后才显示核对通过与实际响应字符串。每次重新启动会复位管理值。

## 06 RTC／SNTP 网络校时

1. 等待新入口加载，设计会自行发出真实 SNTP 请求。
2. 填写时间服务器 t2 相对请求 t1 的偏移，单位为微秒，例如 `250`。
3. 点击「发送本人确认的时间响应」。这一步由测试环境模拟时间服务器，而不是修改 RTC 内部值。
4. 查看「RTC 已同步」、实际 offset、delay；在 ModelSim 中查看 `ts`、RTC UTC 和 t1～t4。

本入口每个新会话只响应一次设计的自动请求。要换参数，重新启动。输入值是服务器时间戳参数，不等于最终 RTC 校正量；最终 offset 使用 `(t2−t1+t3−t4)/2`，delay 使用 `(t4−t1)−(t3−t2)`，由独立参考重算并与真实 RTC 观测值核对。时间格式是 NTP Q32.32。这里没有连接外部真实时间服务器，不能据此宣称绝对 UTC 精度。

## 07 吞吐、应用到应用时延与极差

1. 使用新入口，避免把不同手动实验混入同一统计。
2. 填写实际批量参数。建议帧数 `64`、VL 数 `16`、长度 `1471`、输入间隔 `8100` 周期。
3. 点击确认负载按钮，核对并确认参数。
4. 录制实际结果：吞吐、最大观测时延、同 VL 同长度时延极差和样本数。

统计定义：

- 有效载荷吞吐：已匹配应用载荷总字节数 × 8，除以第一帧应用输入首字节至最后一帧应用输出末字节的时间。
- 应用到应用时延：同一消息的应用输入首字节到应用输出末字节，包含队列等待、发送、测试链路和接收处理；不等同于首字节至首字节。
- 极差：先按相同 VL 与相同载荷长度分组，再求各组时延最大值减最小值，最后取组间最大值。每组至少两个样本；样本不足显示「样本不足」，不会显示为零抖动。
- 数据先通过完整字节、帧格式、FCS、SN、BAG、应用丢失与重复核对，再统计。

只声明页面中的有限负载。最大观测值不是全局最坏时延。故障会话中部分帧有意无法交付，不能使用其已交付子集的吞吐去宣称无丢包性能。

## 08 调度优化前后对照

1. 双击入口，等待两套真实 ModelSim 加载并停下。
2. 阅读界面的固定压力参数：24 帧、16 VL、1471 字节、8100 周期间隔、125 MHz、1 ms BAG，并包含两个管理请求突发。
3. 点击「确认条件并开始两套新仿真」，核对弹窗后确认。
4. 查看两套新的 PASS、吞吐、最大观测时延与极差。结果以本次为准。

本项使用 `service_pressure_011` 的历史已验证配套生产 RTL 源码快照。当前正式 RTL 已增加流水化 MAC 接口，旧仲裁器不能直接混入当前工程。优化前仲裁器来自 `build\logs\service_pressure_010\afdx_service_tx_arbiter_615a.v`，优化后仲裁器来自 `service_pressure_011`。启动时逐文件核对历史 PASS 与源码哈希；其余源码、Testbench、独立参考、时钟、BAG、预期输入、实际应用输入周期及对端实际 GMII 输入必须一致，否则拒绝显示有效对照。01～07 使用当前活动 RTL。本项不会修改活动 RTL 或历史目录，也不是播放旧回归日志。

该新交互负载与历史回归不是同一仿真时序，不能直接套用历史数字。双请求突发是刻意建立的服务排队压力，不能称为满足对端 1 ms BAG 的正常网络负载。对照不保证任何负载下都获得固定倍率提升。

## 09 工程与综合报告

该入口打开工程位置和报告目录，用于展示实现证据；不会执行综合、Implementation、Bitstream 或硬件下载。eLinx 工程与当前交互源码不是自动认定为同一已验证版本，应以对应综合报告的源码指纹为准。动态功能使用前八个 ModelSim 入口。

## 日志与失败处理

每次启动建立 `D:\FPGA\captain_integration\build\interactive_demo\年月日_时分秒_微秒`，绝不覆盖旧验收目录。中文窗口会显示完整路径。

| 文件 | 用途 |
|---|---|
| `plan.json` | 本次输入、用户操作顺序、负载参数、独立预期、源码 SHA-256 |
| `cmd_*.txt` | 测试平台实际读取的外部端口命令 |
| `inputs.csv` | 应用输入的实际周期、VLID、长度 |
| `wire_a.csv`、`wire_b.csv` | 双 GMII 实际发送字节与周期 |
| `ingress_a.csv`、`ingress_b.csv` | 双 GMII 实际返回／对端输入字节、周期与错误标志 |
| `application.csv` | 真实应用输出字节、SOP、EOP、周期 |
| `status.csv`、`rtc.csv` | 只读状态计数、校时时间戳与实际 RTC 计算结果 |
| `verification.json` | 当前场景独立核对结果；失败时有原因 |
| `comparison.json` | 对照结果、相同输入证明、唯一变化源码与两侧指纹 |
| `transcript.log`、`vsim.wlf` | ModelSim 原始记录、波形（只记录所选信号） |
| 同目录 `.v/.sv/.py/.tcl` 快照 | 绑定本次结果的可核查源文件 |

1. 窗口未出现：查看交付目录的 `启动日志\*.err.log`。
2. ModelSim 未加载：查看本次 `transcript.log` 最后的 `Error/Fatal`，检查安装路径和许可。
3. 结果失败：先保留完整本次目录，再看 `verification.json` 的 error。不要删日志或修改旧 run.do 来重跑。
4. 波形看起来平直：查看中文输出是否已有实际接收；工具会定位最近一帧。也可在 ModelSim 使用 Zoom Full，再放大发送与接收附近。
5. 输入被拒绝：检查范围、是否为空、ASCII 限制和长度。修正后重新点击，非法输入不应进入 DUT。
6. 录制失败／超时不能算 PASS。重新启动产生新目录，历史失败记录保持原样。

## 声明边界

交互演示只验证所选 RTL 场景；不会替代已有正式回归。GUI 重放、自动实施自检、人工录屏与正式验收必须分别标明。13 份冻结核心和原有验收证据保持原样。新封装下完整 615A 装卸载会话、外部互操作、异步 PHY、完整物理时序和上板未由这些入口证明。完整 ARINC664P7 条款覆盖 P01 仍未完成，不宣称完整协议合规或认证。

实施验证状态与原始运行路径见工程 `reports\交互演示实现验证.json` 和本交付目录的验证状态说明。后续用户的新运行仍以各自 `verification.json` 为准。
