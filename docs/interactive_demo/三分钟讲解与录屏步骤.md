# 三分钟 PPT 讲解与录屏步骤

目标成片约 170 秒，保留 10 秒余量。先完成仿真与录屏，再将真实片段嵌入对应 PPT 页面。编译等待可从成片裁掉，但本人输入、点击发送、选择故障和修改管理值必须保留；不把自动自检当作人工操作证据。

| PPT 页 | 讲解与建议片段 | 预算 |
|---|---|---:|
| 1 项目与真实链路 | 展示工程顶层、125 MHz，说明应用→双 MAC→真实接收链路 | 12 秒 |
| 2 业务收发与帧格式 | 01：修改 VLID，输入自己的短消息，点击发送；展示实际载荷、SN/FCS与真实波形 | 22 秒 |
| 3 多 VL 与调度 | 02：本人核对并确认 4 VL 负载；展示 1 ms BAG 和实际交付 | 16 秒 |
| 4 双网可靠性 | 03：正常→断 B→仅 B→恢复；每步本人选择并发送不同短消息，展示一次交付与消重 | 30 秒 |
| 5 错误与序号 | 04：本人选择 FCS 错误与正常恢复，再修改异常 SN；展示不交付与错误计数 | 20 秒 |
| 6 管理与校时 | 05：GET→本人 SET 新值→再 GET；06：本人确认服务器时间参数并发送，展示真实 RTC 同步 | 28 秒 |
| 7 性能与优化 | 07：确认参数后展示新实测；08：本人确认相同对照条件，展示两侧新结果和源码唯一差异 | 30 秒 |
| 8 实现证据与范围 | 09：综合报告、源码指纹；说明外部互操作与完整规范覆盖边界 | 12 秒 |
| 合计 | 真实片段与讲解合计 | 170 秒 |

## 录制前

1. 关闭无关弹窗，调整中文控制窗口与 ModelSim 波形的位置。
2. 双击目标入口，等「等待本人操作」。编译过程可以不录入最终短片。
3. 先试一次并保留日志；正式录制重新打开入口，得到独立运行目录。
4. 使用现有录屏软件录制真实桌面。只截取 ModelSim 与控制窗口，不用动画替换仿真。

## 各入口必须保留的镜头

- 01：本人修改 VLID、键入载荷、点击发送；实际应用输出与帧字段。可口述「这里输入的两个 VLID 字节和后面的内容，走的是正式收发 RTL」。
- 02：参数输入、确认弹窗、真实调度结果。可口述「BAG 保持 1 ms，多个 VL 独立排队」。
- 03：本人选择断网和恢复、点击应用、每阶段发送新消息。可口述「A/B 两份经各自校验，应用只交付一份；单网故障仍由另一网交付」。双网同时断开的负例不建议塞进 30 秒主片。
- 04：本人选择错误类型、注入、查看无交付；恢复正确报文后再修改异常 SN。可口述「错误报文经过真实 MAC 和协议校验，异常序号也不能直接进入应用」。
- 05：第一次 GET 的旧值、本人输入 SET 新值、再次 GET 的实际响应。不要只展示窗口中的期望值。
- 06：本人确认 t2 参数并点击响应、真实 `ts` 和 RTC offset/delay。可口述「服务器由测试环境模拟，RTC 使用真实四时间戳计算」。
- 07：本人确认公开负载参数、显示本次新结果。画面必须带样本条件，不使用历史参考值覆盖本次实测。
- 08：本人确认相同压力输入、两套新结果。优化前后不得使用不同负载，也不要省略压力突发条件。
- 09：只展示报告与实现工程。不要点击 Implementation、Bitstream 或 Download。

## 嵌入 PPT

1. 把实际视频复制到自己的 PPT 素材目录，文件名建议为 `02_业务收发_本次日期.mp4` 等。
2. 在相应页面插入本地视频，裁成表格中的建议时长。
3. 设置封面为可读的真实结果画面，并检查播放时仍能看到本人关键操作。
4. 每段字幕写「RTL 仿真」和实际输入条件。性能页注明「最大观测值，非全局最坏值」。
5. 用完整放映计时检查总长，控制在 180 秒以内。

本次交付提供可操作脚本与录屏流程，不把实施自检录像或历史自动回归冒充使用者亲自录制的视频。视频文件由使用者执行关键操作后生成。
