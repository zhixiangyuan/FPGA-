## 入口与数据格式

比赛候选入口为 `rtl/competition/AFDX_top.v`，源码清单由 `scripts/run_competition.py:sources()` 给出。不能与 `rtl/AFDX_top.v` 或 `rtl/submission/AFDX_top.v` 同时编译。后两者仍保留为历史回归入口，不代表本候选的接口语义。

- 时钟 `clk`：125 MHz，周期 8 ns。`reset`：同步、高电平有效。
- `tx_data/tx_valid`：应用输入。每条消息依次输入 VLID 高字节、VLID 低字节及 1～1471 个有效载荷字节，不包含 Ethernet/IP/UDP/FCS。
- 一段连续的 `tx_valid=1` 构成一条消息，至少一个 `tx_valid=0` 周期结束消息。因此不能在消息中间用 valid 空拍表示暂停。
- 首字节必须在 `initialized && tx_ready` 时开始。首字节接受后预留完整数据槽，整条消息按连续 valid 输入；消息内部不再背压。超范围 VL、空消息、不完整 VLID、超长消息整条拒绝并计数。
- `rx_data/rx_valid`：应用输出，格式同为 VLID 两字节加有效载荷。`rx_sop/rx_eop` 标明消息边界；`rx_ready` 控制字节消费，暂停时数据及边界保持。
- GMII A/B 端口：两条独立 8 位 PHY 网络接口，与 `clk` 同步。仿真可各自连接对端或链路模型。跨时钟 PHY CDC 不在本候选范围内。
- `initialized`：4096 条业务接收状态逐条初始化结束；默认需要 4096 周期，即 32.768 μs，不包含 reset 时间。

## 配置与实现

默认业务发送 VL 为 `0x1234..0x12B3`，共 128 条；业务接收范围为 `0x1234..0x2233`，共 4096 条。`TX_VL_COUNT`、`RX_VL_COUNT`、`VL_BASE` 在 elaboration 时配置，不提供动态寄存器装载接口。配置方式符合答疑第 120 行“配置方式不限”；128 条发送 VL 在整机测试中均实际发送。

管理 VL 独立分配在发送业务范围之后：SNMP `0x12B4`、SNTP `0x12B5`、615A `0x12B6`。业务对端默认 MAC `02:00:00:00:00:09`、IP `10.0.0.1`，组播目的 IP `224.224.0.60`；管理对端默认 MAC `02:00:00:00:00:0A`、IP `10.0.0.9`。业务 UDP 端口为 24→23。当前为固定网络 profile，不宣称支持任意地址、分片或全部端口配置。

发送队列为 16 个共享 2 KiB 数据槽，长度上限 1471 字节。调度按 BAG 到期和同 VL 入队先后选择消息，避免队首等待某个 VL 的 BAG 时阻塞其他可发送 VL。发送器保留每 VL 独立 SN 与 BAG 状态，默认 BAG 为 125000 周期（1 ms）。A/B MAC 共同接受同一字节，线上副本保持一致。

每网接收 MAC 使用 16 个原子帧 bank，在完整 FCS 与帧检查通过后提交。业务和管理 parser 各自验证预配置身份；两者同步消费 MAC 字节，不允许一方停顿时另一方重复读取。确认重复或错误的候选可直接释放 parser bank，不逐字节排空整份副本。

SNMP 服务沿用当前增强版六对象与 v1/v2c 请求 profile，将 OID 匹配和响应长度计算分为两个周期，以修复原生 125 MHz 关键路径。响应增加一个内部控制周期，报文字节保持；模块 63 用例和新管理链路均重新比较独立 Golden。

业务接收使用每 VL 83 位同步状态 RAM，分别保存 A/B PSN、最终交付 SN/时间和复位代际。初次接收可建立基线；之后每网按 PSN +1/+2 检查，255→1 回绕，无效普通 SN 仍更新该网 PSN。SN0 为本项目的复位控制，不向应用交付；之后仍要求 SN1/SN2。双网 SN0 通过独立代际关联，防止迟到的另一网 SN0 重新清掉已交付的新代数据。代际比较采用 8 位模序号，假设两网失配少于 128 次发送端重启。

`afdx_redundant_rx` 的默认 `RECOVERY_CYCLES=625000` 表示 5 ms 的 SkewMAX；它只作用于冗余管理，不能绕过每网 IC。窗口内按模 255 前向序号排除重复及迟到旧副本；超时后只对通过 IC 的帧重新建立交付基线。模块参数 `INTEGRITY_ENABLE`、`REDUNDANCY_ENABLE` 支持逐 VL 在 elaboration 时配置，默认全部开启。计时器为 32 位，长时间静默跨完整计数回绕的场景未专项验证。

## 状态口

`status_select` 选择一个 32 位计数值，从 `status_data` 读取。它用于诊断，不参与应用消息握手。

| 选择值 | 状态 |
|---|---|
| 0 / 1 / 2 | 应用入队 / 应用拒绝 / 业务发送完成 |
| 3 / 4 / 5 | 业务应用交付 / 冗余旧副本拒绝 / 完整性错误 |
| 6 / 7 | A / B MAC 丢弃 |
| 8 / 9 | A / B 业务 parser 拒绝 |
| 10 / 11 / 12 | SNMP 请求 / SNMP 响应 / 服务发送错误 |

主业务负载的 16 个 VL 每轮间隔 128000 周期，单帧负载 1471 字节。实际连续注入周期另由证据审计核对，不能用等待 ready 后降低的负载冒称无阻塞。性能是该有界负载的实测值，不承诺任意突发与任意 VL 组合无损。
